    The big idea

    Three words get mixed up constantly. Pin them down first.

    TermWhat it doesEveryday picture
    EncryptionScrambles a message so only the key holder can read it. Everyone can see a secret exists.A locked box sent by courier.
    SteganographyHides the message inside something ordinary, so nobody knows a secret exists.A note written in invisible ink on a postcard.
    Reversible data hiding (RDH)Steganography where, after reading the secret, you can restore the original carrier exactly.Invisible ink that also comes off completely, leaving the postcard like new.

    This project does all three at once. It encrypts the secret, hides it in an RGB image, and makes sure the original image can be rebuilt with zero pixel differences.

    Why "give the photo back" matters

    In medical scans, military imagery, satellite data or court evidence, even a one-value change to a pixel can be unacceptable. RDH lets you attach hidden information, such as a patient ID or an authentication tag, and later remove it without a trace.

    Remember one sentence: decide where to hide using bits you never change, and pack a record of every bit you did change inside the image itself.

    Pixels and bits

    Every colour pixel is three numbers, Red, Green and Blue, each from 0 to 255. Each number is 8 bits.

    1286432168421
    Value Upper part (x & 0xF8) Lower part (x & 7)

    Tap any bit to flip it. Flip a lower (amber) bit and watch the swatch: the colour hardly moves. Flip the top bit and it jumps.

    What x & 0xF8 means

    0xF8 is 11111000 in binary. The & (AND) keeps a bit only where both numbers have a 1. So x & 0xF8 keeps the top five bits and zeroes the bottom three. The report calls this the upper-bitplane representation, Iu = I & 0xF8.

    Changing only the lower three bits moves a value by at most 7, which is about 3% of the 0–255 range. That's why the lower bits are where data goes.

    Bitplanes

    Take bit number 7 of every pixel and you get a black-and-white picture: bitplane 7. Do this for each bit and you get 8 slabs, exactly the stack on the home page. High bitplanes look like the image. Low bitplanes look like noise.

    Key fact for later: if embedding only ever touches the lower 3 bits, the upper 5 bits of the stego image equal those of the cover. The receiver can recompute anything that depends only on the upper bits and get the identical answer.

    The design principle: decision information (upper bits) is kept separate from recovery information (the saved low bits). That separation is what lets one image carry everything.

    The distortion map

    Where can we change pixels without anyone noticing? In busy, textured areas. On a smooth sky, changes stand out.

    Two ways to measure "busy"

    Analytical map. The Sobel operator measures how sharply brightness changes between neighbours (edges). Local variance measures how much the values in a 3×3 window spread out (texture). Both are normalised to 0–1 and averaged.

    DistortionCNN. A small neural network with three branches that look at the image at different scales. It learns patterns the simple formulas miss and outputs a sensitivity map for each of R, G and B.

    Fusion. The two are blended: D = γ·D_CNN + (1 − γ)·D_analytical with γ = 0.6. Both inputs are computed from the upper bits only.

    EMD mod-5

    Hide one digit from 0 to 4 in a pair of pixel values, changing them by as little as possible.

    Take the Red and Green values of a pixel, p1 and p2. Compute f = (p1 + 2·p2) mod 5. That's the digit the pair currently "says". To hide digit d, work out how far off you are, s = (d − f) mod 5, and nudge:

    sChangeWhy it works
    0nothingalready correct
    1p1 + 1f goes up by 1
    2p2 + 1f goes up by 2
    3p2 − 1f goes down by 2, which is +3 in mod 5
    4p1 − 1f goes down by 1, which is +4 in mod 5

    Every digit is reachable by changing one value by 1. Reading it back is simply computing f again.

    The boundary rule

    Try p1 = 103 and hide digit 1. The simple rule says p1 + 1 = 104, but 103 is 01100111 and 104 is 01101000. That +1 carries into bit 3, an upper bit, and the receiver's map would change. So the code searches for the smallest move that stays inside the same block of 8 values (the lower 3 bits only). A valid move always exists, because 8 consecutive values cover all 5 remainders.

    Since values stay inside their block, a pixel can never go below 0 or above 255 either.

    Capacity: one base-5 digit holds log₂5 ≈ 2.32 bits. The starter code converts the ciphertext bytes into a long list of base-5 digits and back.

    3-bit OLSB

    In busy areas, simply overwrite the lowest 3 bits of the Blue value with 3 data bits.

    Data bits to hide (tap to flip)

    Before After Change

    Formula: new = (b & 0xF8) | data. Extract with new & 7.

    The change is at most 7, and it's in the channel people perceive least strongly, in areas that are already noisy. It carries 3 full bits per pixel, more than EMD's 2.32 bits per pair.

    About the "optimal" in OLSB. Classic optimal LSB adds or subtracts 8 after replacement to bring the value closer to the original. Here that's not allowed, because ±8 changes an upper bit. So this project's OLSB is plain 3-bit replacement, restricted to textured pixels. Say this clearly in the report and viva.

    Recovery and security

    Overwriting low bits destroys information. The location map is how the project gets it back.

    The location map

    Before embedding, the sender reads the lower 3 bits of every channel value it will touch: header pixels, the R and G of used EMD pixels, and the B of used OLSB pixels. These are packed in a fixed order and compressed with zlib. After extraction, the receiver writes them back in the same order. Lossy overwriting becomes reversible.

    Encryption, in plain words

    PBKDF2 turns a password into a strong 256-bit key by hashing it many times with a random salt, which makes password guessing slow. AES-256-GCM encrypts the secret and the location map together and adds a 16-byte tag. If anyone changes even one bit of the stego image, or uses the wrong password, decryption fails loudly instead of returning garbage.

    The 64-byte header

    The receiver needs a few facts before it can read anything: the salt, the nonce, the ciphertext length and the thresholds. These go in a fixed 64-byte header stored at a known place. In the starter code, that's the Blue low bits of the first 171 pixels. Here is one layout that works:

    magicversaltnoncect lenEMD bytest1, t2padding

    Bytes: 4 + 2 + 16 + 12 + 4 + 4 + 4 + 18 = 64. Your repo's core/payload.py may use a different order; what matters is that both sides agree.

    Capacity reality check

    The recovery map travels inside the same image as the secret. So the key question is whether there is room left for the secret.

    Count the cost per pixel. An OLSB pixel carries 3 bits, but its map entry stores 3 original bits. An EMD pair carries 2.32 bits, but its map stores 6 original bits (3 for R, 3 for G). zlib can only help if those original low bits have patterns. In real photos, low bits are close to random noise, so they barely compress.

    Map cost is in bits per stored 3-bit value after zlib. Measured on a real photo (the scikit-image astronaut): about 3.4 bits, worse than raw. On a smooth synthetic gradient it can drop well below 1.

    Why this matters for the viva. An examiner who knows RDH may ask: "If you store the original low bits inside the image, what is your net payload on natural photos?" As designed, it's close to zero or negative. It's much better to raise this yourselves with a plan than to be caught by it.

    Ways to make it work (discuss with your guides)

    Give class 0 a genuinely reversible method. Use prediction-error expansion or histogram shifting (the idea behind your MPEH and MCSH baselines) in smooth areas. These create real room without storing original bits, and that room can carry the location map. This also answers "why are class 0 and class 1 different?"

    Store less. For EMD, the receiver only needs to know the move made, not all 6 original bits. Moves are small and can be predicted and compressed far better than raw low bits.

    Report net capacity. Whatever you choose, report BPP after subtracting the map and header, and test on real photos (for example, the USC-SIPI or Kodak sets), not only synthetic images.

    Measuring results

    No single number proves the method works. Each metric answers a different question.

    MetricQuestion it answersGood value

    SSIMDo structures, edges and textures still look the same?Close to 1

    PSNR from MSE

    PSNR = 10 · log₁₀(255² ÷ MSE). Every 10× smaller MSE adds 10 dB.

    Security tests, in one line each

    Entropy checks whether randomness in the image changed. Chi-square spots the tell-tale pairing that LSB replacement leaves in histograms. RS analysis and sample-pair analysis estimate how much LSB embedding happened. Pixel correlation checks whether neighbours still relate the way natural images do. Encryption protects what the secret says. These tests check whether anyone can tell a secret is there.

    Step 2 · EMD with the boundary rule

    def f(p1, p2):
    return (p1 + 2 * p2) % 5

def emd_embed(p1, p2, d):
    need = (d - f(p1, p2)) % 5
    if need == 0:
        return p1, p2
    best = None
    for a in range(-(p1 & 7), 8 - (p1 & 7)):      # stay in p1's block of 8
        for b in range(-(p2 & 7), 8 - (p2 & 7)):  # stay in p2's block of 8
            if (a + 2 * b) % 5 == need:
                cost = a * a + b * b
                if best is None or cost < best[0]:
                    best = (cost, a, b)
    _, a, b = best
    return p1 + a, p2 + b

# test every pair and digit once: 327,680 cases
for p1 in range(256):
    for p2 in range(256):
        for d in range(5):
            q1, q2 = emd_embed(p1, p2, d)
            assert f(q1, q2) == d
            assert q1 & 0xF8 == p1 & 0xF8 and q2 & 0xF8 == p2 & 0xF8
print("EMD ok")

    Step 4 · Analytical distortion map

    SX = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], float)
SY = SX.T
BOX = np.ones((3, 3)) / 9

def conv3(x, k):
    p = np.pad(x, 1, mode="edge")
    out = np.zeros_like(x)
    for dy in range(3):
        for dx in range(3):
            out += k[dy, dx] * p[dy:dy + x.shape[0], dx:dx + x.shape[1]]
    return out

def norm01(x):
    return (x - x.min()) / (x.max() - x.min() + 1e-8)

def analytical_map(upper):
    maps = []
    for c in range(3):
        ch = upper[:, :, c].astype(float)
        grad = np.hypot(conv3(ch, SX), conv3(ch, SY))
        var = conv3(ch * ch, BOX) - conv3(ch, BOX) ** 2
        maps.append(0.5 * norm01(grad) + 0.5 * norm01(var))
    return np.stack(maps, -1)

score = np.round(analytical_map(img & 0xF8).mean(axis=2) * 1024) / 1024
classes = np.digitize(score, [0.15, 0.35])   # 0, 1, 2
    • Check: classes computed from the stego image equals classes from the cover.

    Step 5 · Encryption

    import os
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC

def derive_key(password, salt):
    kdf = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32,
                     salt=salt, iterations=200_000)
    return kdf.derive(password.encode())

salt, nonce = os.urandom(16), os.urandom(12)
ct = AESGCM(derive_key("pw", salt)).encrypt(nonce, b"secret + map", None)
pt = AESGCM(derive_key("pw", salt)).decrypt(nonce, ct, None)  # raises if wrong

    Step 6 · The DistortionCNN (plug-in)

    import torch, torch.nn as nn

class DistortionCNN(nn.Module):
    """Three branches at 3x3, 5x5 and 7x7 scale → one map per channel."""
    def __init__(self):
        super().__init__()
        self.b3 = nn.Conv2d(3, 8, 3, padding=1)
        self.b5 = nn.Conv2d(3, 8, 5, padding=2)
        self.b7 = nn.Conv2d(3, 8, 7, padding=3)
        self.head = nn.Sequential(nn.ReLU(), nn.Conv2d(24, 16, 3, padding=1),
                                  nn.ReLU(), nn.Conv2d(16, 3, 1), nn.Sigmoid())
    def forward(self, x):
        return self.head(torch.cat([self.b3(x), self.b5(x), self.b7(x)], 1))

torch.manual_seed(0)
torch.use_deterministic_algorithms(True)
model = DistortionCNN().eval()        # CPU only, same weights on both sides
x = torch.from_numpy((img & 0xF8) / 255.0).permute(2, 0, 1)[None].float()
with torch.no_grad():
    cnn_map = model(x)[0].permute(1, 2, 0).numpy()
# pass cnn_map into distortion_score(img, cnn_map) in the starter file

    Viva prep

    Questions an examiner is likely to ask, with short answers you should be able to say in your own words.

    Why use the upper bits for the distortion map?

    Embedding changes only the lower 3 bits, so the upper 5 are identical in cover and stego. The receiver computes the same map and the same classes without any side information.

    Why not let the CNN reconstruct the image?

    Neural networks are approximate. RDH needs bit-exact recovery, so the CNN only scores pixels. Exact recovery comes from the saved low bits.

    What happens when EMD needs +1 on a value ending in 111?

    That would change an upper bit. The boundary rule picks a different, equally valid move inside the same 8-value block. A valid move always exists.

    Why EMD in smooth areas and OLSB in textured ones?

    EMD changes a value by about 1, so it's safe where changes would show. OLSB changes up to 7 but carries more bits, which is acceptable where texture hides it.

    How is the payload protected?

    PBKDF2 derives a 256-bit key from the password. AES-256-GCM encrypts the secret and location map and adds an authentication tag that detects tampering or a wrong key.

    What's your net capacity after the location map?

    Prepare this answer carefully. See chapter 8.

    How do you make the CNN deterministic?

    Fixed seeds, eval mode, CPU inference, deterministic algorithms, and scores quantised before thresholding.

    Why does JPEG break it?

    JPEG compression rewrites low bits. RDH assumes a lossless channel. Robustness attacks are reported as a separate study.
